# 飞育教育管理系统 · 建设方案

**版本**：v1.0　**日期**：2026-10　**密级**：内部

---

## 1. 项目背景与目标

### 1.1 背景

集团旗下 2 个校区（本部 + 分校），在校学生、教师、班级、课程、成绩、考勤、收费数据分散在各班主任的 Excel 里，存在以下痛点：

- **学籍分散**：学生档案、学籍变动（转班/休学/复学/退学）靠纸质审批，历史难追溯；
- **成绩口径不一**：各学科自行统计，GPA、及格率、优秀率算法不统一，无法横向对比；
- **考勤滞后**：点名册手工记录，旷课异常要等月底才被发现；
- **收费对账难**：学费应收/实收/逾期靠人工核销，财务与班主任信息不同步；
- **对接困难**：与招生、财务、家校系统无标准接口。

### 1.2 建设目标

| 目标 | 度量 |
| --- | --- |
| 学籍一平台 | 学生从入学到毕业全周期：档案 → 变动 → 状态，一人一档可追溯 |
| 成绩零误差 | GPA/等级/学分绩全部纯函数计算（4.0 制、加权学分绩），可独立单测 |
| 考勤闭环 | 每日登记 → 出勤率统计 → 旷课预警自动触发 |
| 收费透明 | 应收（折扣/减免 Decimal 精确到分）→ 核销 → 逾期预警，收缴率一屏总览 |
| 预警前置 | 规则引擎扫描欠费逾期 / 学业预警（挂科≥2 或均分<60）/ 旷课≥3 三类信号 |
| 开放对接 | 63 个 REST 接口 + OpenAPI 3.0 描述 + 增量同步协议，预留招生/财务/家校对接 |

### 1.3 设计原则

1. **零依赖部署**：仅 Python 3.9+ 标准库（http.server + sqlite3），无 pip install；
2. **纯函数内核**：教育计算（`edu.py`）不碰数据库、无 IO，可独立单元测试；
3. **统一响应包**：`{code, message, data}`，code 与 HTTP 状态码一致；
4. **权限最小化**：6 角色 × 细粒度权限点，接口级强制校验；
5. **幂等与增量**：写接口支持 `Idempotency-Key`，读接口支持版本号增量同步。

## 2. 业务口径

### 2.1 学籍与班级

- 学籍状态：`在读 / 休学 / 转出 / 毕业 / 退学`；状态变更只能通过审批后的学籍变动单生效；
- 转班审批通过后自动迁移班级、重算两班人数；休学/转出/退学同步改学籍状态；
- 班级容量默认 45 人，`在读人数/容量` 实时展示。

### 2.2 成绩与 GPA

- 百分制等级：优 ≥90、良 ≥80、中 ≥70、及格 ≥60、不及格 <60（满分非 100 按比例折算）；
- GPA 4.0 制：90→4.0、85→3.7、82→3.3、78→3.0、75→2.7、72→2.3、68→2.0、64→1.5、60→1.0、<60→0；
- 学分绩（加权平均）= Σ(成绩×学分) / Σ学分；
- 排名同分并列（标准竞赛排名法 1-2-2-4）。

### 2.3 考勤

- 状态五种：`出勤 / 迟到 / 病假 / 事假 / 旷课`；
- 出勤率 = (出勤 + 迟到) / 总记录；旷课天数直接进入风险评分；
- 近 30 天旷课 ≥3 次自动生成预警。

### 2.4 收费

- 应收 = 金额 × (1 − 折扣%) − 减免，Decimal 运算、四舍五入到分（ROUND_HALF_UP）、不为负；
- 状态机：`待缴 → 部分缴费 → 已缴清`，到期日（默认每学期 9-15）未缴清即逾期；
- 缴费核销幂等：已缴清单再次核销返回 noop。

### 2.5 学业风险评分（0~100）

| 信号 | 分值 |
| --- | --- |
| GPA < 2.0 | 30 |
| GPA < 2.5 | 15 |
| 挂科 | 8 分/门，封顶 32 |
| 旷课 | 4 分/天，封顶 24 |
| 欠费 > 1000 元 | 14 |

分级：≥60 险、≥35 警、>0 提、0 正常。

### 2.6 排课冲突

- 班级冲突：同班级同学期同一（星期几，节次）只能排一门课；
- 教师冲突：同教师同学期同一（星期几，节次）只能上一个班；
- 冲突检测为纯函数，`GET /api/schedule?with_conflicts=1` 一次返回课表+冲突。

## 3. 系统架构

```
┌─ frontend/（原生 JS SPA，12 页面，零构建）
│    index.html / login.html / app.js（框架）/ pages.js（页面）
├─ backend/
│    edu.py     业务计算内核（纯函数：GPA/统计/排名/风险/学费/考勤/冲突）
│    db.py      数据层（sqlite3 WAL，21 表 + 8 索引，单号生成，增量版本）
│    seed.py    种子数据（2 校区 / 12 用户 / 10 教师 / 12 班级 / 60 学生 / 10 课程 …）
│    server.py  HTTP 服务（63 路由，五通道鉴权，幂等，CSV 导出）
└─ tests/ + tools/   pytest 49 例 + UI 巡检 13 项 + 冒烟 27 项
```

- **端口**：8025（nginx `/edu/` 反代剥前缀，后端 EDU_PREFIX 留空）
- **鉴权五通道**：`Authorization: Bearer` / `X-Edu-Token` / `Cookie(edu_token)` / `?token=` / `X-Edu-Key`（SHA-256 存储）

## 4. 数据模型（21 表）

| 域 | 表 | 说明 |
| --- | --- | --- |
| 组织 | depts / users / tokens / api_keys | 部门、账号、令牌、接口密钥 |
| 校区 | schools | 校区档案 |
| 教师 | teachers | 工号、学科、职称 |
| 班级 | classes | 班号、年级、班主任、人数 |
| 学生 | students | 学号、班级、监护人、学籍状态 |
| 课程 | courses / schedule | 课程档案、周课表 |
| 成绩 | scores | 按学号×课程×考试×学期唯一（重录覆盖） |
| 考勤 | attendance | 按日按生登记 |
| 缴费 | fees | 应收/折扣/实收/状态机 |
| 学籍 | transfers | 变动单 + 审批 |
| 预警 | risks | 规则引擎产物，处理留痕 |
| 平台 | policies / notices / logs / idem_keys / sync_state / edu_rules | 政策、公告、日志、幂等、同步、参数 |

## 6. 功能清单（12 页面）

1. **工作台**：KPI（学生/教师/班级/课程/出勤率/预警）、考试趋势、学科排行、缴费、待办、公告、预警；
2. **学籍管理**：检索、新增/编辑、档案（成绩+缴费+考勤+GPA）、学籍状态变更；
3. **班级管理**：班级列表、详情（周课表 + 学生名单）；
4. **教师管理**：教师台账；
5. **课程排课**：课程列表、周课表网格、排课冲突高亮；
6. **成绩管理**：学科统计（均分/及格率/优秀率/标准差）、班级排名 TOP10、成绩录入；
7. **考勤管理**：30 天统计、出勤率最低学生榜、登记；
8. **缴费管理**：收缴率 KPI、明细、核销、新建缴费单；
9. **统计报表**：教学/学业/考勤/收费四合一 + 学生名单 CSV 导出；
10. **预警中心**：待处理预警、一键扫描、处理闭环；
11. **政策公告**：政策法规、校园公告；
12. **系统管理**：用户、权限矩阵、接口密钥、增量同步版本、apidoc。

## 7. 对接能力

- 63 路由统一 `{code,message,data}` 包；`GET /api/apidoc` 返回全量路由清单；
- API Key 三档 scope：read / write / full，映射到细粒度权限点；
- 增量同步：`GET /api/sync?version=students:3&entities=students,scores`；
- 幂等：写接口带 `Idempotency-Key` 头，重复请求返回首次结果；
- CSV 导出：`GET /api/reports/export`（UTF-8 BOM，Excel 直开）。
